## 1. 原来有什么具体麻烦

v1.7 的结果摘要开头写了 `Formal=0`。这等于把“这一次是不是论文正式运行”混进了“模拟世界最后是什么样”。同一个世界如果只是换了一个管理标签，理论上不应该得到另一个结果摘要。

另一个问题是清单里只有一个 `valid_for_formal_experiment`。它没有清楚区分：这个模型版本是否已经批准、这一次是否明确要求作为正式数据、运行环境是否合格。

## 2. 这一步实际改了什么

现在领域摘要版本叫 `1.7-domain-v2`。摘要开头只保留模型世界相关内容，删除了日志 Schema 和 `Formal=0`；人口、资源、事件、群体、个人状态、Capsule 和顺序仍然全部参与摘要。

运行清单现在分别写出：

- `formal_model_eligible`：模型版本是否已经完成全部加固；
- `formal_run_requested`：这一次是否明确请求作为正式数据；
- `formal_environment_eligible`：构建和环境是否满足正式要求；
- `valid_for_formal_experiment`：上面三项都为真，并且硬错误为 0 时才为真；
- `formal_eligibility_reason`：用一句可读原因解释为什么当前是 true 或 false。

H1 结束时 v1.7 的 `formal_model_eligible` 仍是 false。只有 H0—H5 全部通过后才开放，所以当前 Development Editor 工程运行仍不会被误标成正式数据。

## 3. 一个简单例子

同一份模拟结果可以先作为普通工程检查保存，也可以勾选“请求正式运行”。现在两份清单会记录不同的请求状态，但结果摘要必须相同。如果模型还没完成加固，第二份清单会直接写明“模型版本还没有正式资格”，而不是只留下一个含义不清的 false。
