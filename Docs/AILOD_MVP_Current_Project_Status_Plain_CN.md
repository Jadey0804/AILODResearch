## 一句话总结

## 已完成的核心部分

### 1. 大规模模拟底座

- 居民身份、职业、资源、住房、维修、政策、行动和事件等核心流程已经具备。
- 大量远处居民按群体推进，玩家附近最多提升 50 个真实居民，不需要让全部人口逐人高频思考。
- ResidentID、HomeID、任务进度和资源预约能够在聚合、解聚合和回访后保持连续。
- 20k 默认规模与 100k 工程压力检查已经跑通；v1.9 已冻结并取得正式实验资格。

### 2. 实验与正式结果

- 已能固定 Seed、记录清单、回放同一结果、检查硬错误，并分别统计模拟阶段成本。
- 480/480 次 200 人准确性运行和 90/90 次 2k/10k/20k 性能运行已完成，全部是同一冻结提交的 Shipping 正式数据，hard error 为 0。
- 统计已按预冻结规则改为 100000 次 paired bootstrap，并生成逐 Seed 图、阈值审计和 TaskActive 原始快照分解。
- 四组正式输出再次通过资格审计；当前代码通过 `AILODResearch` 最终自动回归 73/73，失败 0。
- 20k 下 Proposed 相对 Per-Agent 的配对中位加速约 3.94 倍；10k 开始占优，2k 因固定成本更慢。
- Proposed 的宏观与行为结果明显比 Simple 接近 Oracle；普通 Routine 的 TaskActive 时间相位是主要负面发现。
- 以前的 Development、Pilot 和工程压力检查仍只作为工程证据，没有混入正式统计。

### 3. UE 可视化 Phase 7-0 到 7F

- 可视化、UI、Actor、PCG 和地图只读取模拟，不会成为第二套权威状态。
- 已完成固定世界布局、空间格子查询、World Partition、导航、玩家移动、俯视相机和功能型 UI。
- 已完成低层代理、最多 50 个完整 NPC Actor、点击查看居民和主地图 revisit 连续性修复。
- 已完成望远镜视角、远距候选、持续观察、远处格子临时加载、权威 Lift 和同一 ResidentID 追踪。
- 主地图已移除未跟踪 Fab barn 引用，使用仓库内建筑，并重建 HLOD。
- 低层代理已换成低成本人形轮廓；靠近、点击、持续观察和望远镜继续走同一 ResidentID 的权威 Lift。
- Phase 7F 完成 Development 有画面 24 格工程矩阵和 NavMesh 修正后的 4 格复测；20k/4x World Partition 仍存在 Game Thread 长帧。

## 当前还不完善的地方

1. 望远镜仍没有独立遮挡检测，准星与候选方向在极端 Pitch/FOV 下没有完整验收。
2. World Partition 往返仍会产生明显 Game Thread 长帧；当前证据记录了风险，没有把它包装成稳定 60 FPS。
3. 地图、动画和 UI 仍偏功能型研究 Demo，画面质量不是本论文的核心贡献。
4. Proposed 的普通 Routine `TaskActive` 时间相位与 Oracle 明显不一致，论文必须把它写成限制和负面发现。
5. Proposed 的进程峰值内存高于 Per-Agent，不能宣称总内存节省。
