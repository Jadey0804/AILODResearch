## 1. 这一步用大白话做了什么

B4 以前，新版 v1.7 虽然已经会“整群做事”和“把玩家附近的人恢复出来”，但它还只是一个单独的测试会话。项目真正批量跑实验的入口仍然只会启动旧版 v1.6。

B5A 做的是先把这两边接起来：实验运行器现在可以明确选择新版 v1.7，并且从预热期 D-7 一直按小时跑到 D60。旧版没有被删除，运行器仍能明确选择旧版，所以不会靠改名字把两套结果混在一起。

这一步还加了两道防误用门：

- 新版运行清单明确写 `Schema 1.2` 和 `v1.7_authoritative`，不能伪装成旧版结果；
- 在 B5 全部验收完成前，清单始终写“不能用于正式实验”。目前也只开放无政策场景的工程冒烟和性能模式；政策场景、准确性日志和正式实验入口仍然关闭。

## 2. 实际跑通了什么

固定 Seed `20260810`、总人口 200、无政策场景的新版运行完成了 1608 个小时步，并从生成的运行清单成功重放一次。

本次结果：

- 运行清单：`Spec 1.7`、`Schema 1.2`、`authority_mode=v1.7_authoritative`；
- `valid_for_formal_experiment=false`，没有提前开放正式实验；
- 200 个永久身份在初始化时建立；每小时生产路径扫描身份表的次数为 0；
- 一共只在玩家进入或离开附近时触碰具体居民 120 次；最高同时 Active 为 20，没有超过 50；
- 40,200 人次的社会行动由 1,788 个批量事件表示，没有按参与人数展开成 40,200 个个人事件；
- 最终 Digest 为 `F976DB3886B140FA0A8517390B382D52B650E8B0`，从清单重放后仍然相同；
- 人口、资源、事件、预约、身份和进入/退出检查全部没有硬错误。

这些数字只是“接线是否正确”的工程证据，不是正式性能成绩。

## 3. 测试时发现并修正的问题

第一次完整回归发现：旧 B1 的“v1.7 影子检查”清单也会写 `proposed_model_version=1.7`。重放器如果只看这个字段，就会误把影子检查当成新版权威运行。

现在重放器会看更明确的 `authority_mode`：只有写着 `v1.7_authoritative` 才启动新版权威路径；`v1.7_shadow` 继续重放旧版 v1.6 权威结果。修正后旧 B1 和新 B5A 都通过。

## 5. 这些证据能证明什么

- 正式运行器已经能够明确选择新版 v1.7，不再只能通过隔离测试会话运行；
- 新旧版本不会共用同一套动态状态，也不会因为清单字段相似而重放错模型；
- 新版可以完整走完时钟、固定进入/退出轨迹、写出 Schema 1.2 清单并稳定重放；
- 当前这条工程路径没有每小时扫描全部身份，也没有按人数创建个人事件；
- B0—B4 和旧版运行器没有被本次接线破坏。

## 6. 这些证据还不能证明什么

- 目前新版完整运行只开放了无政策工程冒烟，群体每轮只执行 Routine；Work、买木、砍木、维修、地震和三种政策还没有接入完整 Runner 的小时流程；
- 还没有做 200 人对 Oracle 的 TVD、政策效果、FirstAction 和连续性比较；
- 还没有完成新版 Schema 1.2 的群体时间序列、批量事件、账本和进入/退出明细日志；
- 还没有跑 2k、10k、20k 的确定性和性能对比，也没有跑 50k、100k 压力测试；
- 因此还不能说新版准确、比 Per-Agent 快 3 倍，或已经能用于正式论文实验。
