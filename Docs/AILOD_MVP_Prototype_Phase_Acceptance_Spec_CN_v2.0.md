**协议版本：v2.0**<br>
**模型版本：`[FROZEN] v1.9`**<br>
**领域摘要版本：`1.9-domain-v1`**<br>

**分支：`phase-7-visual-demo`**<br>
**基线提交：`a9385b2`（Phase 6I H6-F）**<br>

## 1. 先用大白话说明 v2.0 是什么

v2.0 不是把居民社会重新设计一遍，也不是把 v1.9 升级成另一套行为模型。

v1.9 仍然决定：居民是谁、有什么资源、房屋怎样、正在做什么、任务何时完成，以及 Cohort 与 Active 怎样安全迁移。v2.0 只决定：玩家在地图上看见谁、NPC 身体在哪里显示、什么时候请求 Lift、画面和 UI 可以读取什么。

因此必须同时显示两个不同概念：

- `DemoProtocolVersion = 2.0`：可视化和互动协议；
- `ModelSpecVersion = 1.9`、`DeterministicDigestVersion = 1.9-domain-v1`：真正的模拟模型和领域摘要。

任何 Phase 7 改动如果改变正式模式的金币、木材、住房、任务、政策、竞争或行动结果，就越过了本文件授权范围，必须停止并另开模型规则讨论。

## 2. 本文件覆盖什么、不覆盖什么

本文件只覆盖早期规格中与 Phase 7 地图、UI、观察者和望远镜有关的展示建议，以及 Phase 7 交接文档中尚未冻结的推荐项。

本文件不覆盖以下 `[FROZEN]` 规则：

- v1.7 的 Identity、Joint State、Batch Claim/Event、Ledger、Capsule、Lift/Restrict 和全局 Active=50；
- v1.8 的正式资格、领域摘要、测量隔离和正式数据边界；
- v1.9 的 HomeID、住房状态、维修归属和住房承诺连续性；
- v1.1—v1.9 中没有被本文件明确列为“纯展示”的其他模型与实验规则。

v2.0 新增的空间位置、VisualHomeSlot、道路、Actor、代理、动画、相机、PCG 和 UI 数据全部属于 Demo/Presentation；它们不得进入 `1.9-domain-v1` 领域摘要，也不得混入正式 480/90 Runs。

## 3. 正式模式和互动 Demo 必须互斥

### 3.1 正式实验模式

- 继续使用 v1.6 冻结的 Day 7/8、14/15、30/31、45/46 固定 Activation Trace；
- 不读取玩家、相机、地图、望远镜或 UI 的观察结果；
- 不加载 Phase 7 的互动命令来选择样本；
- 正式输出和 v1.9 领域摘要规则保持不变。

### 3.2 互动 Demo 模式

- 第一版只运行 `Proposed + v1.9 + StateImport`；
- 必须显式选择 v1.9 权威运行时，不能依赖旧枚举默认值；
- 不执行正式固定 Activation Trace；
- 只根据确定性空间查询、普通镜头和望远镜命令请求 Lift/Restrict；
- 永远标记为 `formal_run = false`，输出放入独立 Demo 目录和记录类型；
- 第一版不提供运行中切换方法或场景的接口。要换方法或场景，必须结束并重新初始化一次运行。

模式必须在初始化时确定，单次运行中不可切换。两种模式不得同时争抢 50 个 Active 名额。

## 4. 权威状态、只读展示和控制请求

系统只允许以下单向连接：

```text
v1.9 权威模拟
    ├─复制/构造只读展示快照─> UI、Actor、动画、调试窗口
    └─接收有类型的互动请求<─ Demo Controller
```

### 4.1 UI 和 Actor 可以读取

- 当前游戏时间、暂停与倍率状态；
- 当前方法、场景、模型版本、权威模式和 Demo 协议版本；
- 王国摘要；
- 最多 50 名 Active 居民的只读身份、住房、动作和任务剩余时间；
- 当前选中居民、望远镜目标、空间查询和 Actor 池诊断；
- 每小时步耗时、Active 数、积压步数等 Demo 性能信息。

快照必须是值拷贝、不可变视图或等价的只读所有权。UI 模块不得获得可写 Ledger、Event、Joint Cell、Identity Registry、Home Continuity Registry 或 Active 内部对象。

### 4.2 UI 和输入可以发送

- 暂停/继续；
- 请求 1x、2x、4x；
- 选择或取消选择居民；
- 提交普通镜头/望远镜观察集合；
- 设定或清除当前追踪居民；
- F1 回到玩家；
- 请求重开一次 Demo。

这些请求只能由 Demo Controller 校验后调用最小公开会话接口。它们不能直接写金币、木材、住房、任务、政策或模拟时钟内部状态。

## 5. 可见居民分为低层代理和完整 Actor

### 5.1 Cohort 低层代理

为了实现“先在远处看到一个人，再用望远镜观察并提升”，允许显示少量 Cohort 低层代理：

- 每个代理必须一对一绑定一个真实存在的 `ResidentID`；
- 代理不是完整 Character/NPC Actor，不占用一份完整 Active Micro 状态；
- 代理不得使用没有真实身份的假人口；
- 代理只显示站立、慢走、轮廓等不承诺精确领域行为的表现；
- 代理不得声称某人正在砍柴、维修、购买木材等，除非该居民已成功 Lift 并从只读快照得到当前动作；
- 代理数量也必须有独立显示预算并通过空间格子选择，不能生成 20k/100k 个代理或隐藏 Actor；具体预算在 Phase 7B 灰盒检查后写入 Demo 配置。

### 5.2 Active 完整 NPC Actor

- 一个可见、可检查的完整 NPC Actor 必须一对一绑定一个真实 Active `ResidentID`；
- Actor 可以放回对象池复用，但 Actor 自身不是居民身份；
- Actor 卸载或回池不能删除居民、改变任务或释放领域资源；
- Actor 的路径、朝向和动画帧属于表现数据，不能自行决定下一项研究行动；
- Actor 不得运行一套会改变研究结果的第二 AI。

## 6. 普通观察、望远镜提升和追踪居民

### 6.1 普通镜头

- 普通镜头从相交的空间格子中选择候选，不能每帧扫描全部人口；
- 远处候选可以先显示为低层代理；
- 普通观察的 Active 建议预算为约 35 人；
- 进入和退出使用约 20% 滞回，避免边缘居民反复出现和消失；
- 距离、视锥和代理预算属于可调 Demo 配置，在空间/地图灰盒后冻结，不属于模型规则。

### 6.2 望远镜

- 望远镜扩展查询距离，只查询瞄准锥体经过的空间格子；
- 中心目标优先，最多附带 4 名上下文居民；
- 中心代理被持续观察达到可调阈值后，Demo Controller 才请求 `LiftResident(ResidentID)`；
- Lift 成功后，代理替换为完整 Active Actor，并读取 v1.9 只读状态；
- 望远镜目标区域可使用一个临时 World Partition Streaming Source；加载完成前允许显示明确的“正在对焦/加载”；
- 关闭望远镜后可以释放远处地图和 Actor，但不能删除居民身份和追踪记录。

### 6.3 当前追踪居民

第一版只保留一个当前追踪居民：

- 成功提升的望远镜中心目标可以设为当前追踪居民；
- 该居民具有最高 Active 保留优先级，可以在 Actor 和地图格子卸载后继续占用一个 Active 名额；
- 玩家后来靠近相应区域时，重新绑定同一 `ResidentID` 和同一身份外观；
- 清除追踪、替换目标或结束运行时，才允许按原子规则 Restrict；
- 第一版保证“同一个人、合理街区/住宅/工作点、合理动作和任务进度”，不承诺离屏数小时后仍处于完全相同的厘米坐标或动画帧。

如果以后需要多个收藏/追踪目标，应另行增加明确上限和淘汰规则，不能无界占用 Active 名额。

### 6.4 50 人名额

- 全局硬上限始终为 50；
- 初始软预算：普通观察约 35、望远镜最多 5、切换/承诺/追踪缓冲约 10；
- 预算是 Demo 调度建议，不改变 v1.9 的 50 人硬门；
- 名额不足时，先计算完整替换集合，再原子提交；失败后保持旧集合不变；
- 同优先级以稳定 `ResidentID` 排序，保证回放可重复。

## 7. 固定空间布局是唯一展示空间来源

### 7.1 固定布局包含什么

Phase 7 建立一份独立、版本化、只读的 Visual World Layout，至少包含：

- `DistrictID` 和街区范围；
- 道路样条线或路线图；
- `VisualHomeSlotID` 与住宅展示位置；
- 林场、木材采购点、市场等 `WorkAnchorID`；
- 必要的站位、入口和路径连接；
- 空间格子编号和格子内稳定居民名单；
- 布局版本、地图 Seed 和生成配置。

`HomeID -> VisualHomeSlotID` 可以是多对一：20k 居民不要求 20k 栋可见建筑。VisualHomeSlot 只决定展示位置，不替代 v1.9 的 HomeID 和房屋状态。

### 7.2 唯一允许的数据方向

```text
固定 Visual World Layout
    ├─> NPC 空间目录、路线和观察查询
    └─> PCG 房屋/树木生成与 World Partition 内容
```

NPC 展示层和 PCG 必须读取同一份固定布局。NPC 不得扫描当前已生成或已加载的房屋 Actor 来判断哪里有房屋、道路或工作地点。

地图格子、建筑 Actor 或 PCG 内容被卸载时，Visual World Layout 和 ResidentID 的空间映射仍然存在；加载状态不得改变模拟领域状态。

### 7.3 空间连续性

Phase 7 可以保存独立的展示空间记录，例如街区、住宅槽位、工作点、当前路线、路线进度、最后展示时间和追踪标记。它只对画面位置负责：

- 不保存或覆盖金币、木材、HomeState、任务结果或政策；
- 不进入正式领域摘要；
- 普通离屏人口不得逐帧更新路线；
- 当前追踪居民等少量对象可以按游戏小时或由时间公式低频推进；
- 同一 Seed、布局版本和命令轨迹必须得到同一空间选择结果。

## 8. PCG、World Partition 和 HLOD 的最小边界

### 8.1 第一版怎样使用 PCG

- 作者只需要手工绘制少量道路样条线、圈出住宅/森林等区域并放置林场、采购点等重要地标；
- PCG 使用固定 Seed，沿道路和区域批量生成房屋、树木和简单装饰；
- 第一版在编辑器中生成并 Bake/保存结果，不在运行时重新规划整个王国；
- 固定 Seed 不能单独当作冻结证据；生成结果、布局版本、Graph 版本和关键配置也必须保存；
- Phase 7 第一版不引入无限世界、动态生态或运行时随机村庄。

### 8.2 运行时加载

- World Partition 负责按玩家/相机的 Streaming Source 加载和卸载已保存的地图格子；
- HLOD 负责在完整格子卸载时保留远处房屋和树林的简化轮廓；
- 望远镜可以临时增加第二个小范围 Streaming Source；
- 建筑和树木优先使用无 Tick 的 Static Mesh、ISM/HISM、Foliage 或等价轻量表现；
- 大量运行时 PCG、动态碰撞重建和动态 NavMesh 重建不进入第一版，除非后续性能证据证明必要。

### 8.3 作者与 Codex 的地图协作

- Codex 负责数据契约、最小代码连接、资产命名要求、验证规则和逐步部署说明；
- 作者负责在 UE 编辑器中创建/放置必须人工判断的道路、区域、地标和 Mesh 资产；
- 任何需要作者操作 UE 的阶段，检查点文档必须写出：打开哪个菜单、创建什么资产、使用什么名称、在哪个面板修改哪个字段、预期看到什么、怎样验证、失败时怎样停止；
- 不假设作者预先会 PCG、World Partition、HLOD、NavMesh、Data Layer 或空间格子；首次使用时必须先用大白话解释用途；
- 未给出步骤和验收方法前，不要求作者自行猜测或部署。

## 9. 地图、镜头和操作

- 新建独立的 Phase 7 World Partition Demo 地图，不直接把现有 `ThirdPersonMap` 当最终研究地图；
- 左键地面：玩家移动，相机处于跟随模式时一起移动；
- 左键 NPC：选择并查看该 NPC；
- WASD：自由移动相机；
- 自由相机不会因为玩家移动自动弹回；
- F1：相机自动回到玩家并恢复跟随；
- 第一版右键不承担必要功能；
- 暂停模拟后，相机、选择和 UI 仍可操作。

## 10. 时间、人口和运行终点

- Day -7 至 Day 0 在加载阶段预热，玩家从 Day 0 进入；
- Day 60 停止模拟，显示结果并提供重开，不扩展成无限游戏；
- 1x 初始定义为每 1 个真实秒请求推进 1 个游戏小时，2x/4x 成倍；
- 每帧最多实际执行一个 `StepHour`；积压留到后续帧，不能为了追赶在单帧连续执行很多小时；
- 上述倍率可在运行调试后调整，但必须作为 Demo 配置记录，不得改变正式实验时间语义；
- 2k 总人口用于快速开发和自动验证；
- 可视化 Demo 默认 20k 总人口；
- 100k 只作为可选压力档，不是默认可视化目标，也不能用 NullRHI 旧结果承诺有画面帧率。

## 11. UI 技术边界

- 功能型 UI 采用 Dear ImGui；原始仓库为 `https://github.com/ocornut/imgui`；
- 原始 Dear ImGui 不是可直接投入 UE 的完整插件；当前 UE 适配候选为 `https://github.com/VesCodes/ImGui`；
- 在接入前必须固定具体提交，并验证 UE 5.4 Editor、PIE、输入和 Development 打包；
- 第一版只使用一个简单窗口，不启用非必要的多视口、Docking、远程绘制或复杂主题；
- Phase 7A 先完成只读数据接口，GUI 插件兼容检查和实际窗口接入放在后续 UI 步骤；
- 第三方代码的许可证、固定提交和本地放置方式必须写进相应检查点；
- UI 不得通过 Dear ImGui 指针、回调或 Blueprint 绕过只读边界。

## 12. 互动记录和正式数据隔离

互动 Demo 至少记录：

- Demo 协议版本、模型版本、布局版本、Seed、人口、场景和方法；
- 暂停/倍率请求；
- 普通观察集合和望远镜目标；
- Lift/Restrict/追踪请求及结果；
- 空间查询候选访问数；
- Active 集合变化和 50 人上限结果；
- World Partition/Actor 加载诊断和每小时步耗时。

这些记录只用于 Demo 调试、回放或额外望远镜实验。它们不得写入正式 Run Manifest，也不得因为“使用同一个 v1.9 模型”而被冒充为正式研究数据。

## 13. Phase 7-0 到 7F 的最小实施顺序

每一步只完成本步范围，生成独立检查点，经作者确认后再提交并进入下一步。

### Phase 7-0：规则和边界

- 只写本 v2.0、权威索引、交接补充和大白话检查点；
- 不修改 Source、Content、插件或配置；
- 检查点文件：`Docs/AILOD_MVP_Phase7_0_Checkpoint_CN.md`。

### Phase 7A：无画面互动连接层

- 增加明确的 Demo 运行模式并显式选择 Proposed v1.9；
- 固定轨迹与互动模式互斥；
- 提供原子观察集合、释放/追踪请求和只读展示快照；
- 记录并回放互动命令；
- 先跑 Phase 7 前基线，再用无地图自动检查证明不改领域结果；
- 检查点文件：`Docs/AILOD_MVP_Phase7A_Checkpoint_CN.md`。

### Phase 7B：无画面空间、代理候选和望远镜选择

- 建立固定布局数据契约、ResidentID 空间映射和空间格子索引；
- 输入镜头/望远镜查询，输出稳定代理候选和 Active 请求；
- 实现优先级、滞回、一个追踪目标和空间连续性；
- 验证 20k→100k 查询不退化为全人口逐帧扫描；
- 检查点文件：`Docs/AILOD_MVP_Phase7B_Checkpoint_CN.md`。

### Phase 7C：地图、PCG、相机、移动和功能 UI

- 先验证并固定 UE ImGui 适配插件；
- 建立独立 World Partition 灰盒地图；
- 作者按逐步说明画道路/区域并放重要地标，PCG 编辑器生成固定房屋和树木；
- 接通 World Partition、HLOD、导航、点击移动、WASD 自由相机、F1 和时间 UI；
- 先不做复杂 NPC 动作；
- 检查点文件：`Docs/AILOD_MVP_Phase7C_Checkpoint_CN.md`，必须包含作者部署步骤。

### Phase 7D：低层代理与完整 NPC Actor

- 实现有真实 ResidentID 的轻量代理；
- 实现最多 50 个完整 NPC Actor 的对象池和只读绑定；
- 映射基础地点、路径和占位动画；
- 验证代理升级、Actor 回池和重新绑定不改模拟；
- 检查点文件：`Docs/AILOD_MVP_Phase7D_Checkpoint_CN.md`，必须包含作者放置/绑定资产步骤。

### Phase 7E：望远镜连续性

- 实现远距查询、观察时间、临时 Streaming Source、Lift、追踪和后来重新找到同一 ResidentID；
- 保存并回放命令；
- 验证同一脚本、Seed 和布局得到同一目标；
- 检查点文件：`Docs/AILOD_MVP_Phase7E_Checkpoint_CN.md`，必须包含作者部署和演示步骤。

### Phase 7F：可视化总验收

- 完整编译和全部自动检查；
- 验证 v1.9 正式模式领域摘要和硬门未变；
- 测量 2k 开发档和 20k 默认 Demo；100k 只做可选压力；
- 测量快速镜头、代理、50 个 Actor、PCG/World Partition 加载、望远镜反复开关和帧时间；
- 输出完整演示操作、已知限制和论文中能说/不能说的结论；
- 检查点文件：`Docs/AILOD_MVP_Phase7F_Checkpoint_CN.md`。

## 14. 每个阶段检查点的固定结构

Phase 7-0、7A、7B、7C、7D、7E、7F 的检查点都必须包含：

1. 大白话说明本阶段解决了什么；
2. 本阶段明确没有做什么；
3. 修改的文件和公开接口；
4. 自动检查、人工检查和原始证据；
5. 每项证据能证明什么、不能证明什么；
6. 已知问题和可调 Demo 参数；
7. Codex 下一步要做什么；
8. 项目作者下一步要做什么；
9. 如果作者需要操作 UE，给出逐步点击、命名、预期结果和停止条件；
10. 明确写出“等待作者确认，未获确认不得进入下一阶段”。

## 15. Phase 7 的硬停止条件

出现以下任意情况必须停止当前步骤，不得用临时绕过进入下一阶段：

- 正式固定 Activation Trace 与互动镜头同时运行；
- UI、Actor、代理、Blueprint、行为树、PCG 或地图加载直接写领域状态；
- 正式 v1.9 领域摘要或冻结语义发生未批准变化；
- 可见完整 NPC Actor 没有真实 Active ResidentID；
- 低层代理没有真实 ResidentID，或表现尚未恢复的精确领域行为；
- 相机/望远镜每帧扫描全部人口；
- 生成 20k/100k 个 Actor、Character 或逐居民运行时路径；
- PCG/World Partition 卸载导致居民身份、HomeID、任务或空间映射消失；
- Demo 日志进入正式实验目录或被标记为正式 Run；
- 单帧为了追赶倍率连续执行多个 `StepHour`；
- 未经作者确认就进入下一阶段、提交或 push。
